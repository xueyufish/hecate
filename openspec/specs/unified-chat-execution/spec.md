# Unified Chat Execution Specification

## Purpose

将配置了工具的 agent 的 chat 执行收敛到统一 Pregel 运行时：一条执行路径产生一致的工具事件、审批记录、结束原因与恢复语义，HTTP 层只做协议适配。经功能开关渐进迁移，直连循环保留为回退。

## Requirements

### Requirement: 有工具 agent 经统一运行时执行

配置了工具的 agent 的 chat 请求(流式与非流式)的路由 SHALL 按解析后的生效开关决定:workspace 级覆盖(如设置)优先于全局 `CHAT_TOOL_LOOP_ENGINE_ENABLED`,两者均缺省时为关闭。生效开关开启时执行 SHALL 经平台入口执行服务与 Pregel chat 图完成,产生引擎事件(含 `TOOL_CALL`/`TOOL_RESULT` 回执);开关关闭时 SHALL 保持直连循环行为不变。会话 SHALL 保持路径亲缘:`session_resume`/会话续接沿用该会话已建立的路径,一次进行中的流式请求不受并发开关变更影响。引擎 ToolWorker 的 guardrail 装配 SHALL 与直连路径等价(`middleware_chains`、`denial_tracker`、`event_store` 完整下传)。带知识库或增强功能的请求 SHALL NOT 丢失 agent 配置的工具。workspace 覆盖的每次变更 SHALL 写入放量记录(workspace、操作者、旧值→新值、时间);兼容期直连循环不具备引擎路径的恢复/回放保证,G2 关闭前不得对新路径宣称可靠副作用恢复。

#### Scenario: 开关开启时有工具 agent 走引擎

- **WHEN** 生效开关为开启且配置了工具的 agent 发起 chat 请求
- **THEN** 执行经 Pregel 图完成,事件日志含配对的 `TOOL_CALL`/`TOOL_RESULT`

#### Scenario: 开关关闭时行为不变

- **WHEN** 生效开关为关闭(默认)
- **THEN** 有工具 agent 的 chat 请求走直连循环,行为与迁移前一致

#### Scenario: 关态行为有真实入口钉住

- **WHEN** 全局开关关闭且无 workspace 覆盖,经真实 HTTP 入口发起有工具 agent 的流式与非流式请求
- **THEN** 请求走直连循环且响应语义与迁移前一致;引擎事件日志不因该请求产生条目;直连循环不经引擎事件日志、无持久回放保证的限制保持显式文档化,不因引擎路径成为推荐路径而被默写抹去

#### Scenario: workspace 覆盖优先于全局开关

- **WHEN** 全局开关为 `false` 而某 workspace 覆盖为开启
- **THEN** 该 workspace 的请求走引擎路径,其他 workspace 不受影响

#### Scenario: 会话续接保持路径亲缘

- **WHEN** 某会话既有轮次经直连循环完成,生效开关随后变更
- **THEN** 该会话的续接/恢复仍沿用直连路径,不因开关变更中途切换

#### Scenario: 覆盖变更写入放量记录

- **WHEN** 修改某 workspace 的覆盖值
- **THEN** 放量记录写入 workspace、操作者、旧值→新值与时间,可审计查询

#### Scenario: 增强分支不再丢失工具

- **WHEN** 带工具的 agent 携带 `kb_ids` 发起请求(生效开关开启)
- **THEN** agent 配置的工具在执行中可用(不再仅客户端工具)

### Requirement: 流式中间迭代静默

开关开启的流式 chat SHALL 保持既有可观察语义：中间工具迭代的 LLM 输出 SHALL NOT 作为内容块流式下发，仅最终答案流式输出；工具执行进度不冒充内容块。结束原因（finish_reason）语义与直连路径一致。

#### Scenario: 中间迭代不出现在流式内容中

- **WHEN** 一次需要两轮工具调用的流式 chat 完成
- **THEN** SSE 内容块仅包含最终答案文本，中间迭代的 LLM 文本（如有）不下发

#### Scenario: 结束原因一致

- **WHEN** 同一请求分别在开关开启与关闭下执行至自然结束
- **THEN** 两者的 finish_reason 语义一致（stop / tool-calls 耗尽等对应关系明确）

### Requirement: 跨入口执行一致性

同一 agent 的同一请求经 HTTP、MCP（`agent_chat`）、workflow 三入口执行时，SHALL 产生一致的工具事件序列、审批记录与结束原因——差异仅在传输适配层。审批在流式路径保持同步问询语义（引擎 interrupt 语义的流式表达留作后续演进）。

#### Scenario: HTTP 与 MCP 工具事件一致

- **WHEN** 同一配置工具的 agent 分别经 HTTP chat 与 MCP `agent_chat` 执行相同输入
- **THEN** 两者的事件日志含相同序列的 `TOOL_CALL`/`TOOL_RESULT`（tool_name 与 execution 配对语义一致）

#### Scenario: 审批记录一致

- **WHEN** 需审批的工具调用分别在开关开启的 HTTP 路径与引擎路径（MCP）执行
- **THEN** 审批记录（APPROVAL_ASKED/DECIDED 语义）等价产生

### Requirement: 引擎路径具备真实入口证据

引擎路径的正确性 SHALL 以真实入口测试证明,不以内联替换执行服务的 mock 分支测试替代:覆盖流式与非流式、多轮工具调用、审批拒绝、确定性策略拒绝、断线/恢复、取消,以及跨请求多轮会话连续性,并核对 tool call/result 配对、审批拒绝记录的传递与终止类别的呈现。断线/恢复证据 SHALL 包含**真实网络传输上的中途断连**(真实 socket 服务端与客户端,SSE 流在执行中途断开),缓冲式进程内传输的完成后快照用例不满足该证据;断连后的事实断言 SHALL 基于持久存储以新会话查询。HTTP、MCP(`agent_chat`)与 workflow(已有部署身份的 Agent 子任务路径)三入口 SHALL 分别积累证据;某入口缺证据时,该入口不得视为已收敛。直连循环作为回退路径 SHALL 保留关态真实入口钉住与其显式限制文档。真实入口证据按入口逐条积累;默认开关保持关闭。是否翻转全局默认 SHALL 以可查询的决策记录为准:逐入口真实证据清单、放量审计核对、剩余入口证据缺口与翻转前置条件;无决策记录不得翻转。

#### Scenario: 真实 HTTP 入口多轮流式

- **WHEN** 经真实 HTTP/SSE 入口发起需要两轮工具调用的流式 chat
- **THEN** 最终答案按既有 SSE 语义下发,事件日志含两轮配对的 `TOOL_CALL`/`TOOL_RESULT`,中间迭代不下发内容块

#### Scenario: 审批拒绝经真实入口传递

- **WHEN** 经真实入口触发需审批工具且审批被拒
- **THEN** 拒绝记录产生并传递到该入口的响应语义,与直连路径等价

#### Scenario: 确定性策略拒绝不终止且留痕

- **WHEN** 引擎路径经真实入口触发策略的确定性拒绝(非审批流)
- **THEN** 拒绝产生可查询记录,对话不因此终止,响应语义与直连路径等价

#### Scenario: 会话中取消在模型边界生效

- **WHEN** 引擎路径的流式会话执行中被客户端断开,循环准备进入下一次模型调用
- **THEN** 迭代边界取消检查生效,执行以 cancelled 类终止理由收尾;进行中的工具轮恰好完成一次且状态持久;同会话恢复不重复执行已完成副作用

#### Scenario: 跨请求多轮会话连续

- **WHEN** 同一会话经真实入口连续发起多轮请求(引擎路径)
- **THEN** 后续轮次延续前轮历史与结果,路径亲缘保持,前轮已决回执不重复执行,tool call/result 配对跨轮完整

#### Scenario: 断线后恢复

- **WHEN** 流式请求中断后经会话续接恢复
- **THEN** 恢复沿用该会话既有的路径与状态,不产生重复工具副作用

#### Scenario: 真实传输中途断连后恢复

- **WHEN** 流式执行在真实 TCP/SSE 传输中途被客户端断开(首 chunk 已下发、执行未完成),随后经同会话续接恢复
- **THEN** 断开前已成功的工具副作用在恢复中零重复;恢复依据持久存储中的事实回填回执,事件、终态与投影以新数据库会话可查且与执行一致

#### Scenario: MCP 入口引擎路径证据

- **WHEN** 经 MCP `agent_chat` 入口以确定性模型/工具执行多轮、策略拒绝与取消恢复场景
- **THEN** 工具事件序列、审批记录与结束原因与 HTTP 入口等价,差异仅在协议适配层

#### Scenario: Workflow 子任务入口引擎路径证据

- **WHEN** 经 workflow 入口以已有部署身份的 Agent 子任务(具名子任务 adapter)执行多轮工具与拒绝场景
- **THEN** 子任务的工具事件与终态经平台持久事实可查,与 HTTP 入口的执行语义一致;独立 workflow 自身的 Run 身份不在本证据内

#### Scenario: 入口缺证据不切默认

- **WHEN** 某入口尚无真实入口证据
- **THEN** 该入口不宣称收敛,全局默认开关不因此翻转

#### Scenario: 默认开关翻转以决策记录为准

- **WHEN** 评估是否将全局默认翻转为引擎路径
- **THEN** 存在可查询的决策记录:逐入口真实证据清单、放量审计核对结论、剩余入口证据缺口与翻转前置条件;缺该记录时默认保持关闭

### Requirement: 跨轮恢复回执反映持久事实

跨轮或断线后的恢复 SHALL 依据持久执行事实恢复工具回执:已记录成功的动作 SHALL 优先回填持久记录的真实结果内容(通道历史或持久账本),不重复执行副作用。真实结果内容不可恢复时:写类动作 MUST 停止并进入显式对账停止类别,不得将占位文本作为工具回执交给模型继续推理;只读类 MAY 按既有安全语义重新执行。停止类别与投影/信封的呈现 SHALL 与既有停止语义一致。

#### Scenario: 断线后真实结果回填

- **WHEN** 执行中途断线,已成功工具的结果内容已持久记录,续轮恢复再次遇到同一 tool call
- **THEN** 恢复回填持久记录的真实结果,业务工具不被第二次调用

#### Scenario: 结果内容不可恢复时停止而非占位推理

- **WHEN** 已记录成功的写类动作在恢复时无法取得真实结果内容
- **THEN** 执行以显式对账类停止,工具回执不以可推理的占位文本交给模型,Run 终态与停止类别可查

#### Scenario: 只读动作内容缺失可安全重执行

- **WHEN** 已记录成功的只读动作在恢复时无法取得结果内容
- **THEN** 按既有只读安全语义允许重新执行,不触发对账停止
