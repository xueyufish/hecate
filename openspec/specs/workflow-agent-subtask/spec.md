# workflow-agent-subtask Specification

## Purpose

定义确定性 Workflow 调用自主 Agent 子任务的步骤契约:扩展步骤声明(模式、输出 schema、期望产物与持久审批等待),产物校验先于父流程推进,子任务终态回调幂等,使父流程不依据 Agent 自称完成直接推进,并在重复/迟到回调下不重复产生推进或业务副作用;声明持久审批等待的子任务停车期间父流程保持持久等待,拒批经核实回调按失败策略收敛,父子进程重启后从持久事实恢复推进。

## Requirements

### Requirement: 子步骤声明扩展且向后兼容

Workflow 子步骤声明 SHALL 支持可选的执行模式、输出 schema、期望产物与持久审批等待(`approval_wait`,布尔)字段;仅含 `goal` 的既有负载继续按原语义受理。新增字段类型不合法或与保留字段冲突时,计划解析 SHALL 显式拒绝并给出可定位错误,不得静默忽略。步骤声明的 `approval_wait` 为真时 SHALL 盖章进子任务的持久化输入,使子任务派发装配启用持久审批等待;未声明或为假的子任务行为不变,持久审批不默认全局开启。

#### Scenario: 旧格式继续可用

- **WHEN** 提交的子步骤仅包含 `goal`
- **THEN** 计划按既有语义受理,行为与本变更前一致

#### Scenario: 声明产物与输出 schema 的步骤受理

- **WHEN** 子步骤声明执行模式、输出 schema 与期望产物且类型合法
- **THEN** 计划解析成功,字段进入子任务派发上下文

#### Scenario: 非法字段显式拒绝

- **WHEN** 子步骤的输出 schema 不是合法 JSON Schema 或模式取值不在受支持集合,或 `approval_wait` 不是布尔值
- **THEN** 提交被拒绝,错误指明字段与原因,不产生子任务

#### Scenario: 审批声明进入子任务持久化输入

- **WHEN** 子步骤声明 `approval_wait` 为真并经真实提交创建子任务
- **THEN** 子任务的持久化输入携带该声明,子任务派发装配据此启用持久审批等待;同一步骤计划重新解析产生相同的输入形状

### Requirement: 产物校验先于父流程推进

子任务进入终态时,父流程 SHALL 先按步骤声明完成产物/输出校验再推进:产物缺失或输出不符合 schema 时,该步骤按失败处理并路由到步骤声明的失败策略。父流程 MUST NOT 仅凭子任务自称成功而推进到下一步骤。

#### Scenario: 产物缺失不推进

- **WHEN** 子任务报告成功但声明的期望产物缺失
- **THEN** 该步骤按失败策略处理,父流程不推进到下一步骤

#### Scenario: 输出不符 schema 按失败路由

- **WHEN** 子任务产物存在但内容不符合声明的输出 schema
- **THEN** 该步骤按失败策略处理,校验错误可查询

#### Scenario: 校验通过正常推进

- **WHEN** 子任务成功且产物与输出 schema 均通过校验
- **THEN** 父流程按计划推进到下一步骤

### Requirement: 子任务终态回调幂等

父流程对子任务终态回调 SHALL 按 (父任务, 步骤序号) 幂等处理:同一子任务的重复回调与终态已应用后的迟到回调 SHALL 被显式拒绝(可查询的回执),MUST NOT 触发第二次推进、第二次失败路由或任何业务副作用。

#### Scenario: 重复回调只推进一次

- **WHEN** 同一子任务的终态回调被投递两次
- **THEN** 父流程只应用一次推进,第二次回调收到显式幂等回执,无额外副作用

#### Scenario: 迟到回调在状态推进后到达

- **WHEN** 父流程已按某回调推进,之后另一迟到回调到达
- **THEN** 迟到回调被拒绝且留痕,父流程状态不被改写

#### Scenario: 快速子任务不丢失终态回调

- **WHEN** 子任务在父任务保存等待状态之前已到达终态
- **THEN** 父任务保存等待后复查子终态并通过已验证回调推进,不重复提交或执行子任务

### Requirement: 失败策略覆盖校验失败与子任务失败

步骤失败策略(至少 `fail` 与 `await`)SHALL 同时覆盖子任务执行失败与产物/输出校验失败两类来源,两类来源的处置结果可区分;`await` 语义沿用持久等待(等待/对账),不在本能力内重新定义。

#### Scenario: 校验失败走 await 语义

- **WHEN** 步骤声明 `on_failure: await` 且产物校验失败
- **THEN** 父任务进入等待/对齐处置状态而非直接失败,处置详情可查询

#### Scenario: 子任务执行失败与校验失败可区分

- **WHEN** 两次步骤失败分别来自子任务执行失败与产物校验失败
- **THEN** 两次的失败来源类别在任务详情中可区分

### Requirement: 子任务持久审批与父流程收敛

声明持久审批等待的子任务进入 `waiting_approval` 期间,父 Workflow SHALL 保持持久等待,不提前推进(审批等待不是子任务终态,经核实的终态回调不触发)。子任务审批被拒时,其终态 SHALL 经既有核实回调链收敛父流程,且失败来源与子任务执行失败可区分;父流程按声明的 `on_failure` 策略处理(`fail` 失败 / `await` 待对账),不得等待到超时才收敛。父、子执行进程重启后,任务关联、审批绑定与消费状态、工具回执和流程位置 SHALL 从持久事实恢复:批准后的子任务续跑经原生续跑门完成,产物校验通过后父流程才推进。重复、迟到或伪造回调不得重复推进父流程(既有幂等语义不变)。

#### Scenario: 子任务审批等待期间父流程不推进

- **WHEN** 声明审批等待的子任务停车在 `waiting_approval`
- **THEN** 父任务保持其持久等待状态,等待契约未被消费,流程位置不变

#### Scenario: 拒批经核实回调收敛父流程

- **WHEN** 子任务的审批决定为 rejected,父流程步骤声明 `on_failure: fail`
- **THEN** 子任务转 `approval_rejected` 终态后,经核实的回调唤醒父任务,父任务按失败策略失败且失败来源可归因为审批拒批,不等待到超时

#### Scenario: 组合进程重启后恢复推进

- **WHEN** 子任务停车在 `waiting_approval` 时子执行进程被真实终止,审批与续跑后,或父等待中父子执行进程先后重启
- **THEN** 任务关联与流程位置从持久事实恢复,子任务续跑完成且产物校验通过后父流程恰好推进一步,已完成动作不重复执行

#### Scenario: 伪造回调不能替代审批事实

- **WHEN** 子任务仍在 `waiting_approval` 时收到声称子任务已成功的伪造回调
- **THEN** 回调被既有核实语义拒绝(声明状态与子任务真实状态不符),父任务状态不变

#### Scenario: 拒批终态提交后回调失败可恢复

- **WHEN** 子任务拒批终态已提交，自动回调失败或进程在回调前退出
- **THEN** 终态事件从已有持久 outbox 重放；即使平台事件已经投影，回调也须完成核实与应用后才确认交付；重复投递不重复推进父流程，重试耗尽按既有 relay 机制显式登记 gap
