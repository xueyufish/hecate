# Design

## Context

见 proposal.md。现有研究方案包含 step1—step19、P01—P08 场景映射和已完成的基线勾选项。RuntimePort 是出站依赖边界，自包含测试主要证明导入隔离；生产装配仍涉及 WorkflowExecutionService、平台 ORM 和 composition。独立安装及无控制面执行不能据此认定已实现。

## Goals / Non-Goals

**Goals:** 在同一方案中贯通交付边界、状态所有权、执行宿主、授权与发布规则、步骤依赖及验收；保留历史证据。

**Non-Goals:** 不实现 Runtime、不建立车商产品、不升级正式 specs、不改历史基线或宣称生产支持；不新增强制供应商或数据库。

## Decisions

- 原有 step 编号不变，以子步骤和迭代后缀承载增量，避免重排全部引用。
- 契约、执行组件、管理平台是交付边界；执行内核和宿主分离，进程内调用和服务入口共享装配。替代方案“仅抽内核包”无法消除平台装配依赖。
- 独立运行先于受管连接认证。step5 提供安全收窄的技术预览，生产写入还需 step6/7、最小发布与相应 step16；避免为了早交付跳过可靠性与授权。
- 将平台治理状态与宿主执行事实分别定义；独立本地任务接管采用显式登记及映射，不改写历史或双重调度。
- 无中心服务与无网络访问分轴描述；离线撤权的传播限制必须显式暴露。
- 本次是文档变更，按 OpenSpec 官方 `skip_specs` 机制不生成行为 delta；正式行为规格由后续实现 change 提出。

## Risks / Trade-offs

- [修改范围分散造成前后矛盾] → 同步总表、详细步骤、功能目录映射、里程碑与验收矩阵，并做交叉检查。
- [把新目标标成已实现] → 原 step1 已完成项逐条保持，新任务全部未勾选；历史测试标注为历史证据。
- [Runtime 与宿主各造一套逻辑] → 计划明确共享装配，独立发行包不复制主应用代码。
- [生产闭环依赖循环] → 最小本地制品校验和审计先交付，完整集中发布和观测后扩展；分开技术预览与生产门槛。

## Migration Plan

修订研究方案及定位摘要，明确正式 P1—P5 明细由 feature catalogue/roadmap 管理并在 step2 迁移；做结构/语义核验及 OpenSpec 校验。仅文档回退，无数据迁移。change 留待正常评审、合入和用户触发归档；本次不推送。
