## Why — 动机

当用户向同一对话快速发送多条消息时，当前系统会并发处理它们。这会导致竞态条件：消息可能以错误的顺序到达 LLM，内存块可能因并发写入而损坏，上下文组装可能产生不一致的结果。功能目录将此描述为"会话内顺序处理任务，新消息自动排队等待，避免并发冲突"。

## What Changes — 变更内容

- 添加**每会话锁**机制 — 每个对话每次只处理一条消息
- 添加**自动排队** — 发往繁忙会话的新消息将排队，按 FIFO 顺序处理
- 在 **API 响应中添加队列状态** — 客户端可以看到消息是已排队（位置）还是正在处理
- 添加**队列超时** — 排队消息在 5 分钟后过期，防止无限等待
- 添加**前端队列指示器** — 聊天 UI 在等待时显示"Queued (position 2)..."

## Capabilities — 能力

### New Capabilities — 新增能力
- `task-queuing`：每会话顺序消息处理，带自动排队和超时

### Modified Capabilities — 修改的能力
- `session-memory`：添加会话内顺序处理的需求

## Impact — 影响范围

- **Backend**：`conversation.py` — 添加会话锁管理器，将 `chat()` 包装在锁中
- **Backend**：`chat.py` — 在响应头中添加队列状态
- **Frontend**：聊天页面 — 消息排队时显示队列指示器
- **Tests**：并发消息处理测试
- **无外部依赖** — 使用 `asyncio.Lock` 按会话管理，内存队列
