# Design

## Context

动机见 proposal.md。当前执行应用服务直接持有 PregelRuntime；CoordinatorWorker 将 TaskDAG 编译为子图，子图使用 InMemoryCheckpointStore。主方案将内部机制留给 step5e 决定，unified-chat-execution 主规范则明确要求开启开关时走 Pregel。已有 durable task、Action Ledger、审批续跑、上下文处理和父子流程证据可以复用，不能把新架构规划当成这些事实已经发生变化。

## Goals / Non-Goals

**Goals:** 在原方案内固定目标职责、依赖、迁移与退出条件，使自主 Controller、结构化 Workflow 和共享可靠执行形成可实施的连续切片；同步实践对照中的裁决。

**Non-Goals:** 本次不新增运行时代码或 ABC，不移动包，不修改主 specs 或既有 ADR 的 Accepted 状态，不触发路由切换。保持原步骤、Feature ID 和证据，完整 SkillHub、其他流程引擎、程序执行和外部 Runtime 不作为首次交付前置。

## Decisions

- 将自主 Agent Controller 与图执行分开，共享持久化操作和治理契约。拒绝将所有模型行为强制编译为 GraphConfig；也不允许多个执行方式各自维护账本、审批和等待机制。逻辑职责先固定，物理包由具名消费者和依赖证据决定。
- Dynamic Plan 是提案和已接受版本；实际 Task/Run/Action 及验收事实驱动进度。TaskDAG→Pregel 是结构化策略，Todo、直接行动与局部计划可以共存，不新建第三套引擎。
- 先设计共同决策/动作/等待/Child Run 接缝，再完成 Controller 与图执行消费。入口契约收敛可并行，默认路由切换必须等待新路径的恢复与治理验证；活跃 Run 固定原实现和状态格式。
- 将语义创作与执行确定性分轴：发布型 Workflow 固定可验证版本；本次运行的计划修订不自动发布。程序执行按需求和隔离能力单独认证。
- 主方案只保存决策、工作包与门槛，详细实现留给后续 change。既有 specs/ADR 冲突以明确迁移清单登记，不直接改写历史为已实现的新规范。实践对照只更新 Hecate 的推论和实施建议，公开项目的未验证细节不扩写。
- 复用现有 Task 的目标、验收标准与责任字段，将执行、交付、验收和业务效果分开；目标/标准修订须经有权主体接受。Harness 可建议完成或继续，可信控制执行累计预算、权限、取消和版本检查，不新建 Goal Runtime。
- Evidence Receipt 是动作、业务确认及产物版本的授权视图，引用稳定身份和版本；消息位置、模型声明及成功状态本身不能证明业务目标达成。运行时验收与发布评测分别记录，按任务决定 advisory 或 blocking。
- 文件工作区是平台 Workspace 内的独立资源，生命周期不等于 Agent、Run 或 Sandbox。最小产物/文件恢复随启用文件任务的切片交付；执行 Checkpoint 不回滚文件，数据库 fencing 不自动约束远端写入，按真实后端能力限制接管和并发。
- 子执行的同步/异步、可重算/可恢复、单项/批量分别声明；非独立持久化不豁免动作账本。完整 Batch 复用已有作业和 Runner，按需增加队列、背压与结果管理，不另建恢复体系。
- 用户自定义的 Problem_Lab 验证属于 step1—step19 完成后的独立事项：删除由工作簿向平台要求、功能清单及验收门槛的映射和专项条款。平台自身的授权、恢复、可替换性与发布质量要求保留；历史基线/测试不删除，已完成 SC 项只去除当前计划中的 P 映射措辞。
- 以“企业级 Agent 原生、持久化、强治理智能执行平台”表达目标定位。内置 Runtime 是核心产品能力和执行责任主体；独立集成与受管运行是两种交付方式，控制面管理执行宿主、Deployment 和 Run，而非业务 App 本身。开发、发布、协作属于围绕执行核心的能力，不与核心差异并列堆叠。
- 使用完整 spec-driven 并保留 design；本次仅文档，按 CLI 约定 skip_specs，不创造无运行行为对应的产品 delta。

## Risks / Trade-offs

- [计划与现行规范冲突] → 明确区分目标和现状；step2/3 在实现前以 delta specs 和新 ADR 收敛冲突，旧行为保持到对应切片通过。
- [共同底座变成泛化虚拟机或新事件真源] → 仅涵盖具名消费者需要的持久操作，复用现有事务、账本、事件和 outbox，明确字段 owner。
- [新目标污染历史交付] → 保留已交付行、原测试记录和默认开关；新增未完成项独立列出。
- [重排放大近期范围] → M-A/I-Cb 保持近期目标，I-Ca 单独验收；最小 Child Run 提前，企业团队和生态继续条件性扩展。

- [完成门禁或工作区扩大首次范围] → 单 Agent 最小交付/验收前移；文件与沙箱仅对启用 profile 必需，完整 Memory/Knowledge、Team、Batch 不成为前置。
- [旧环境默认按 Agent 共享] → 在后续实现中迁移 agent-environment 的绑定与权限语义；旧文件不自动向新任务或委派范围开放，先核对归属及版本再复用。

## Migration Plan

本次修改主方案和实践对照后验证链接、表格、编号、勾选与库存元数据；运行实现的迁移列入方案工作包。文档回退只恢复规划文本，不改变执行状态。后续实现先对新 Run 分流，保留旧实现及状态读取；影子比较不得双执行外部副作用。
