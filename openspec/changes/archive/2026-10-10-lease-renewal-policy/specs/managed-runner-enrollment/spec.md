## MODIFIED Requirements

### Requirement: 限时授权租约约束受管动作且断连不自授权

平台按 `security-claims` 语义签发限域限时租约(签发者、受众、部署绑定、主体、动作范围、期限、防重放);宿主 MUST 验证签发者、受众、部署绑定与期限后接受新工作。断连后租约到期,新受保护动作 MUST 停止;宿主 MUST NOT 切换为本地自授权或更换信任根。profile SHALL 显式配置最大陈旧窗口与过期后的拒绝行为;需在线判定的高风险动作在断连时停止。

同 Run 的第二个及后续受保护动作在当前租约 nonce 已消费时,宿主 MUST 采用**有界等待续租**策略:等待通道下一次 pull 安装新租约,等待预算 SHALL 是显式声明的策略参数(声明为宿主断连/续租窗口),超窗后 MUST 转为显式证据化拒绝(执行失败、停止后续工具、零业务副作用)。等待只覆盖"新租约未到达"这一瞬态;动作范围越界、签发者/部署绑定不匹配 MUST 立即拒绝,不等待。已决动作(账本已有确定结果)的回放 MUST NOT 消耗租约 nonce。

租约 nonce 消费记录 MUST 跨宿主进程重启保持:重启后回注已消费且未过期的旧租约 MUST 被拒绝,不得再次武装动作;`update` 在安装新租约前 MUST 拒绝已消费 nonce 的重放租约(不得替换当前租约);其余无效租约(篡改、过期、绑定不匹配)按既有语义安装,由派发边界以精确原因拒绝并留证据。

#### Scenario: 租约过期后新受保护动作停止

- **WHEN** 断连超过租约期限后宿主收到新的受保护动作请求
- **THEN** 拒绝执行且不产生本地自签授权,拒绝留证据

#### Scenario: 防重放拒绝旧租约

- **WHEN** 已消费或已过期的租约被重放使用
- **THEN** 宿主拒绝该租约并留拒绝记录

#### Scenario: 多写动作经续租逐一授权

- **WHEN** 同一 Run 依次执行多个受保护动作,通道按 pull 节奏持续安装新租约
- **THEN** 每个动作恰好消耗一个新租约 nonce 并恰好执行一次业务调用,业务调用计数与动作数一致,无动作因续租等待失败

#### Scenario: 停发租约后有界拒绝零副作用

- **WHEN** 通道停止 pull(失联),在途 Run 的下一个受保护动作等待续租超过声明预算
- **THEN** 该动作被显式拒绝并留证据,Run 以失败终态收敛,拒绝后不再发生任何业务调用,已执行的前序动作事实保持不变

#### Scenario: 范围越界立即拒绝不等待续租

- **WHEN** 受保护动作请求的数据域在当前租约 scope 之外
- **THEN** 立即拒绝(不进入续租等待),nonce 不被该动作消费路径回填为可用,拒绝留证据

#### Scenario: 重启后回注已消费租约被拒绝

- **WHEN** 宿主进程重启后,已消费且未过期的旧租约被回注安装
- **THEN** 该租约不得通过验证武装任何受保护动作,拒绝留证据;重启后的新 pull 安装的新租约正常可用
